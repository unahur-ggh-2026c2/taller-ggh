# Changelog

Registro de cambios relevantes del proyecto.

El formato sigue una estructura simple basada en versiones y fechas.

---

## [Versión] — AAAA-MM-DD

### Agregado

- Nueva funcionalidad.
- Nuevo recurso.

### Cambiado

- Modificación de una funcionalidad existente.
- Actualización de documentación.

### Corregido

- Corrección de un error.
- Corrección de documentación.

### Eliminado

- Funcionalidad retirada.
- Recurso eliminado.

---

## [Versión anterior] — AAAA-MM-DD

### Agregado

- ...

### Cambiado

- ...

### Corregido

- ...

---

## Formato mínimo

Para proyectos pequeños también puede utilizarse una estructura más simple:

```md
## [1.1.0] — 2026-08-26

- Agrega búsqueda de usuarios.
- Actualiza documentación.

## [1.0.0] — 2026-08-01

- Primera versión del proyecto.
```

---

## Criterios

Registrar cambios que sean relevantes para quienes utilizan, mantienen o revisan el proyecto.

No es necesario documentar cada modificación interna o cada commit.

---

## Tipos de cambio

| Sección     | Uso                              |
| ----------- | -------------------------------- |
| `Agregado`  | Nueva funcionalidad o recurso    |
| `Cambiado`  | Modificación de algo existente   |
| `Corregido` | Corrección de un problema        |
| `Eliminado` | Funcionalidad o recurso retirado |

---

> **El CHANGELOG resume la evolución del proyecto para las personas; el historial de Git conserva el detalle técnico de los cambios.**
