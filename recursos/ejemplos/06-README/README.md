# Ejemplo 06 — README

Ejemplo de un README pequeño pero suficientemente completo para presentar un proyecto.

---

## Estructura

```text
06-README/
├── README.md
└── src/
    └── tareas.py
```

---

## README de ejemplo

El `README.md` podría contener:

````md
# Gestor de Tareas

Aplicación de consola para registrar y consultar tareas.

## Objetivo

Permitir administrar una lista simple de tareas desde la línea de comandos.

## Tecnologías

- Python
- Git
- GitHub

## Requisitos

- Python 3.x

## Instalación

Clonar el repositorio:

```bash
git clone URL_DEL_REPOSITORIO
cd 06-README
```

## Uso

Ejecutar:

```bash
python src/tareas.py
```

## Ejemplo

```text
$ python src/tareas.py

# 1. Estudiar Git
# 2. Completar ejercicio
# 3. Revisar README
```

## Estado

Proyecto educativo en desarrollo.

## Próximos pasos

* Agregar persistencia.
* Incorporar eliminación de tareas.

````

---

## Qué debería poder responder el README

Al leerlo, otra persona debería poder identificar:

```text
qué es
   ↓
para qué sirve
   ↓
qué necesita
   ↓
cómo instalarlo
   ↓
cómo ejecutarlo
   ↓
en qué estado está
```

---

## Probar las instrucciones

Una vez escrito el README, seguir sus propios pasos:

```text
README
  ↓
instalación
  ↓
ejecución
  ↓
resultado
```

Si alguna instrucción no funciona, corregirla antes de publicar.

---

## Checklist

```text
[ ] El nombre del proyecto es claro.
[ ] La descripción explica qué hace.
[ ] El objetivo está definido.
[ ] Las tecnologías principales están indicadas.
[ ] Los requisitos están indicados.
[ ] La instalación funciona.
[ ] El ejemplo de uso funciona.
[ ] El estado del proyecto está indicado.
[ ] Los próximos pasos son coherentes.
[ ] No hay enlaces rotos.
```

> **Un buen README permite que otra persona empiece a entender y utilizar el proyecto sin necesitar una explicación oral.**
